# 画面のテスト（E2E）

`tests/*.js` は「この関数は正しく動くか」を見ます。ここは
**「利用者が実際に操作したらどうなるか」**を見ます。

関数が全部正しくても、ボタンが繋がっていなければ旅程は作れません。
実際、データ読込中に押すと行き止まりになる不具合は、単体テストが
482件すべて通っている状態で残っていました。

## 動かす

本体には依存パッケージがありません（`node --test tests/*.js` は
そのまま動きます）。E2E だけはブラウザが要るので、**別立て**にしています。

```bash
npm i -D playwright-core          # 1度だけ
npx playwright install chromium   # 1度だけ

python3 -m http.server 8000 &     # リポジトリの根で。別の端末でも可
node tests/e2e/run.mjs            # http://localhost:8000 を見にいきます
```

ブラウザの場所を指定したいときは環境変数で渡します。

```bash
CHROME=/path/to/chrome BASE_URL=http://localhost:8000 node tests/e2e/run.mjs
```

外へ出られない環境（CI など）では `E2E_OFFLINE=1` を付けます。
外部への通信をブラウザの側で即座に切るので、相手が黙って応えない
ときの数十秒×区間数を待たずに済みます。「外が使えなくても旅程が
できるか」を見るのが目的なので、切られること自体は失敗になりません。

```bash
E2E_OFFLINE=1 node tests/e2e/run.mjs
```

GitHub Actions では `.github/workflows/test.yml` の `e2e` ジョブが、
この形で毎回動かします。

## 読み上げ・色・構造のテスト（a11y.mjs）

`run.mjs` は「操作したらどうなるか」を見ます。`a11y.mjs` は
**「読める状態か」**を見ます。旅行のアプリは、明るい屋外の画面で
読まれます。薄い灰色の注意書きは、そこでいちばん先に消えます。

```bash
npm i -D axe-core                 # 1度だけ（playwright-core に足して）
python3 -m http.server 8000 &
node tests/e2e/a11y.mjs
```

条件の画面と旅程の画面を、明るい配色・暗い配色・携帯の幅で測ります。
色は配色で変わり、重なりは幅で変わるので、1つでは足りません。

判定は [axe-core](https://github.com/dequelabs/axe-core) に任せます。
自分で「たぶん読める」と決めるより、比率を測ってもらうほうが確かです。
この仕組みを入れたときに見つかったもの:

- 補助の文字（欄名・注意書き）が 3.4:1 しかなく、AA（4.5:1）に届かない
- 「無理なく回れます」の緑が 1.7:1 で、ほとんど読めない
- 立ち寄り先のカードが `role="button"` で、中のリンクへ行けない
- つまみに `<label>` が無く、見出しが h1 から h3 へ飛んでいた

## 見ていること

```
ページを開く
  ↓ データを読み終わるまでボタンが押せないこと
希望を入力する
  ↓
旅程をつくる
  ↓ 要約 → 3案 → 旅程 → 言葉で直す → 詳細 の順で出ること
案を選び直す
  ↓ 選んだ案に切り替わること
「言葉で直す」で組み直す
  ↓ 何をどう読み取ったかが返ること
```

外部APIのキーが無くても通ります（語句検索と距離推定に落ちるだけで、
旅程はできます）。地図タイルが取れない環境でも通します。
